SCIP-Jack – A solver for STP and variants with
parallelization extensions
Gerald Gamrath, Thorsten Koch, Stephen J. Maher, Daniel Rehfeldt, and Yuji
Shinano
Zuse Institute Berlin, Takustr. 7, 14195 Berlin, Germany,
{gamrath, koch, maher, rehfeldt, shinano }@zib.de
Abstract. In this article we describe the impact from embedding a 15
year old model for solving the Steiner tree problem in graphs in a state-
of-the-art MIP-Framework, making the result run in a massively parallel
environment and extending the model to solve as many problem variants
as possible. We end up with a high-performance solver that is capable of
solving previously unsolved instances and, in contrast to its predecessor,
is freely available for academic research.
1 Introduction
The Steiner tree problem in graphs (STP) is one of the classical NP -hard prob-
lems [1]. Given an undirected connected graph G = (V,E ), costs c : E→ Q+
and a set T ⊂ V of terminals, the problem is to ﬁnd a minimum weight tree
S⊆G which spans T .
The STP is said to have a variety of practical applications. However, applica-
tions that involve solving the pure STP are rarely seen in practice. Nevertheless
the pure STP can be found in applications such as routing in computer net-
works, VLSI design and phylogeny [2], but even VLSI design is more suitably
formulated as a rectilinear Steiner tree packing problem. The lack of real-world
applications for the pure STP is highlighted by the fact that from the thousands
of instance collected by the authors in the SteinLib [3] very few have practi-
cal origins. However, there exist numerous applications that include STPs as a
subproblem or that are formulated as a particular variant of it.
The announcement of the 11th DIMACS Challenge, initiated our work with
an investigation into the model and code described in [4]. Taking this and the
developments of the last 15 years, throughout this paper we show:
– in Section 2 the impact of transitioning from a simple self-made branch-and-
cut code to the use of a full ﬂedged, state-of-the-art MIP-Framework,

– in Section 3 how to employ the versatility of MIP models to solve a class of

time. Further details on this can be found in [5, 6].
2 From simple hand tailored to oﬀ-the-shelf
state-of-the-art
In this section we present the solver SCIP-Jack. We ﬁrst describe the STP
model used and the simple self-made branch-and-cut code Jack-III. The exten-
sion of the MIP solving framework SCIP, by the use of STP speciﬁc plugins, to
a full-scale branch-and-cut based STP solver will then be explained. Solving the
STP, and related variants, using SCIP proﬁts from the available state-of-the-
art MIP solving algorithms. The impact of combining SCIP and Jack-III to
form SCIP-Jack is then analyzed and discussed through some computational
experiments.
The model employed in SCIP-Jack uses the directed cut formulation . For
this we brieﬂy delineate how to transform a STP to its directed equivalent the
Steiner arborescence problem : Given an undirected graph ( V,E ) and a set of
terminals T , we replace each edge {u,v}∈ E by two anti-parallel arcs ( u,v )
and (v,u ). Let A denote this set of arcs, and D = (V,A ) the resulting digraph.

is a subgraphS⊆D such that (VS,AS) contains exactly one directed path fromr
tot for allt∈T\{r}. There is a one-to-one correspondence between (undirected)
Steiner trees in G and Steiner arborescences in D which contain at most one of
two anti-parallel arcs. Thus, if we choose arc weightsc(u,v) := c(v,u) :=c{u,v}, for
{u,v}∈ E, the Steiner tree problem can be solved by ﬁnding the minimal Steiner
arborescence with respect to c. Introducing variables ya for a∈ A with the

Since the model potentially contains an exponential number of constraints
a branch-and-cut approach is employed. Constraints that are violated are sep-
arated during the execution of the algorithm. Jack-III uses this model and
implements its own branch-and-bound search. Strong branching is used with a
depth-ﬁrst search node selection while attempts are made to generate feasible
solutions with a primal heuristic.
Our reimplementation of SCIP-Jack is based on the academic MIP solver
SCIP [7]. Besides being one of the fastest non-commercial MIP solvers [8], SCIP
is a general branch-and-cut framework, emplyoing a plugin-based design to pro-
vide a simple method of extension to handle speciﬁc problem classes.
The preprocessing of SCIP-Jack mainly relies on STP-speciﬁc reduction
techniques as implemented in [4], with a few additions. They have a signiﬁcant
impact on the solving time for many instances, see [9, 2]. There is much scope for
improvement, considering the immense advancements in this area, most saliently
the much stronger and faster reduction techniques employed by [2]. The absence
of some of these fast and eﬀective reduction techniques is indeed considered by
us to be the most predominant blemish of SCIP-Jack and we would purport
that an enourmous speed-up for almost all variants could be achieved by imple-
menting those techniques.
The branch-and-bound search is organized by SCIP: we use the default hy-
brid branching rule [10] which combines strong branching and pseudo costs with
history information like conﬂict and inference scores. Node selection is done with
respect to a best estimate criterion, interleaved best bound and depth-ﬁrst search
phases [11].
Three STP-speciﬁc primal heuristics have been implemented, a construc-
tive heuristic based on [12], an improvement heuristic [13] and a recombination
heuristic. The improvement heuristic is called whenever a new solution is found
that is within the three best solution known so far. It is in fact a combination
of the three local search heuristics vertex insertion, key-path exchange and key-
vertex elimination, as described in [13], with the most impact, by far, being
achieved by the latter two. For the implementation in SCIP-Jack some alter-
ations had to be made in order to adapt the algorithms, originally designed for
undirected problems, to our model (Formulation 1). The third heuristic is based
on a recombination approach, where several good solutions are merged. A STP
is then solved on the corresponding graph and followed by the application of
the improvement heuristic. This approach could be implemented using SCIP
without much diﬃculty as SCIP not only stores a number of best found solu-
tions, but also allows to create and solve a subproblem during the superordinate
solving process.

Solving the Steiner tree problem in graphs
While the focus of this paper is set on the versatility of SCIP-Jack in terms of
being capable of solving a large variety of STP variants, it is still important to
demonstrate its abilities to handle vanilla STP instances. There are many STP
instances submitted to the DIMACS challenge with varying degrees of complex-
ity. We present computational experiments on a subset of these to demonstrate

All computational experiments described were performed on a cluster of Intel

Computational Results The test sets SP, I640, and PUC are all relatively
hard test sets from SteinLib, still containing unsolved instances. SCIP-Jack
solves most of the instances of the SP test set and about two thirds of the I640 set.
On average, only a couple of nodes and a few minutes are required, although there
are also instances which need a signiﬁcant amount of branching or several hours
to solve. The PUC test set is even harder and more than half of the instances

a lot of time is spent in the separation process. Nevertheless, SCIP-Jack seems
to be competitive to the results presented in [15], at least for the test set vienna-
i-simple.
3 From single problem to class solver

by SCIP-Jack. Speciﬁcally, transformations required to render these variants
tractable for our solver are presented. Computational results will be shown for
most of the discussed variants in order to demonstrate the eﬀectiveness of our
generic STP solver. Throughout this section the weights of an (undirected) edge

The Steiner Arborescence Problem
Since the Steiner tree solver transforms each Steiner tree problem to a Steiner
arborescence problem (SAP), as described in section 2, the branch-and-cut sub-
struction and the constructive heuristic can be used without much further imple-
mentation. However, the same does not apply for the presolving techniques and
the local heuristics. As no Steiner arborescence problems have been published
in the DIMACS Challenge, this section goes without computational evaluations.
Nevertheless, the Steiner arborescence problem is of importance in the context
of the DIMACS Challenge as several of the following Steiner variants can be
reduced to this.
The Rectilinear Steiner Minimum T ree Problem
The rectilinear Steiner minimum tree problem (RSMTP) can be described as
follows: given a number of n∈ N points in the plane, the task is to ﬁnd a
shortest tree consisting only of vertical and horizontal line segments, containing
alln points. The RSMTP isNP -hard, as proved in [16], and has been the subject
of various publications, [17–19]. In addition to this two-dimensional variant,
a generalisation of the problem to the d-dimensional case, with d ≥ 2, will
be considered, having real-world applications in up to eight dimensions, e.g. in
cancer research [20].
Hanan [21] proved that the RSMTP can be restricted to the grid obtained
by constructing vertical and horizontal lines through each given point of the
RSMTP. Subsequently, this observation and its multi-dimensional generalisa-
tion [22] is exploited in order to adapt the RSMTP to our solver. Given a
d−dimensional, d∈ N\{ 1}, RSMTP represented by a set of n∈ N points
in Qd, the ﬁrst step involves building a d−dimensional Hanan grid. Thereafter,
a STP P = (V,E,T,c ) is constructed in a straightforward way: The vertex set
V is constructed by assigning each intersection point of the grid a vertex. Anal-
ogously,E is obtained by interconnecting the vertices V according to the grid
structure, i.e. in such a way that two vertices inV are adjacent if and only if their
corresponding intersection points are adjacent in the grid. The set of terminals
T consists of all vertices in V corresponding to one of the original n RSMTP
points. Finally, the cost of an edge {v,w}∈ E is deﬁned by the (Euclidean)
distance of the two d-dimensional points in the grid corresponding to v and w
respectively.
Claim 1 Each solution to the STP obtained from a RSMTP as delineated above,
can be transformed to the original RSMTP, by applying the described bijective
mapping. Optimality is preserved.

There are a few necessary remarks regarding the implementation in SCIP-
Jack. First, by default presolving is not used for RSMTP problems within our
solver. This is spawned by the problem speciﬁc structure, which proved to be
distinctively recalcitrant to the reduction techniques employed by SCIP-Jack
leading to an exceptionally poor performance of the presolving. Second, we do
not expect this simple approach to be competitive with highly specialized solvers,
such as GeoSteiner [17] in the cases d = 2 and d = 3. However, in dimensions
d≥ 4 there seems to be a lack of specialized solvers, so this approach might be
of help for such instances. Still, it is not practical to apply the grid transforma-
tion for large instances in high dimension, as the number of both vertices and
edges increases exponentially with the number of dimensions. A potential reduc-
tion technique for the RSMTP is the full Steiner trees (FST) generation [23].
However, presolving and reduction techniques are not used by SCIP-Jack for
this variant and as such we have not implemented this approach. Although this
might be done in the future, especially with respect to possible multi-dimensional
generalizations.
A variant of the RSMTP is theobstacle-avoiding rectilinear Steiner minimum
tree problem (OARSMTP). In these problems it is required that the minimum-
length rectilinear tree does not pass through the interior of any speciﬁed axis-
aligned rectangles, denoted as obstacles. SCIP-Jack is easily extended to solve
the OARSMTP with a simple modiﬁcation to the Hanan grid approach applied
to the RSMTP. This modiﬁcation involves removing all vertices that are located
in the interior of an obstacle together with their incident edges. Since there is no
competition for this variant in the DIMACS challenge and for the OARSMTP,
unlike the RSMT, optimal solutions to all instances have already been published,
we refrain from conducting any computational experiments.
Finally, it must be noted that the related Euclidean Steiner tree problem ,
which diﬀers from the RSMTP insofar as the rectilinear distance is replaced
with the Euclidean distance, cannot be handled by our solver. It seems diﬃcult
to render this problem solvable for SCIP-Jack, as a clear structure, such as the
Hanan grid for the RSMTP, is ostensibly missing.

less than 0.1 seconds.

The structure of the PCSTP and SAP given from Transformation 3 does not
permit the direct application of any of the heuristics previously presented and
only a limited set of reduction techniques are employed bySCIP-Jack. However,
a variation of the constructive heuristic is deployed. Instead of starting from
diﬀerent vertices, the starting point is always the (artﬁcial) root. In each run all
arcs between the root and non-terminals (denoted by ( r′,t ) in Transformation
3) are temporarily removed, except for one. A tree is then computed on this new
graph, using the same process as the original constructive heuristic. The same
amount of iterations as of the original constructive heuristic are executed by
default (100 before the solving process, 10 after each LP), each with a diﬀerent
choice of the arc not to remove. By adjusting the shortest path data of the nodes
adjacent to the root, the recomputation of the shortest paths in every iteration
is not necessary.

The Degree-Constrained Steiner T ree Problem
The degree-constrained Steiner tree problem (DCSTP), is a STP with an ad-
ditional degree constraint for each node. The objective is to ﬁnd a minimum
solution to the STP such that the degree of each node in the Steiner tree is
not larger than the given limit. The DCSTP is implemented by just adding the
additional degree constraints for each node as linear constraints to the directed-
cut-formulation (Formulation 1). Additionally, a variation of the constructive
heuristic is used, slightly altered in such a way that the degree constraints are
striven to be taken into consideration.

The Group Steiner T ree Problem
The group Steiner tree problem (GSTP) is another generalization of the Steiner
tree problem, where the concept of terminals as a set of vertices to be inter-
connected is extended to a set of vertex groups: Given an undirected graph
G = (V,E ), edge costs c :E→ Q≥0 and a series of vertex subsets T1,...Ts⊂V ,
s∈ N, a minimum cost tree spanning at least one vertex of each subset is re-
quired. By substituting each terminal t by{t} every STP can be considered as
a GSTP, the latter also beingNP -hard. Although a generalization, each GTSP
instance (V,E,T 1,..,T S,c ) can be transformed to a STP using the following
scheme: Enlarge the graph by adding for each group Ti a new vertex ti and
edges{ti,v} of high cost to each v∈V . Regarding the set {t1,...,t s} as termi-
nals, each solution to the STP on the enlarged graph corresponds to a solution
to the GSP , obtained by removing all artiﬁcial edges {ti,v}, i = 1,...,s , v∈V .
This approach has already been deployed by [26] to solve group Steiner tree
problems and demonstrated to be competitive with specialized solvers at the
time of publishing. Since no GSTP instances are published in the course of the
DIMACS Challenge, we refrain from presenting a more formal delineation of the
transformation and refer to [26] instead.
The Hop-Constrained Steiner T ree Problem
The hop-constrained Steiner tree problem (HCSTP), compared to a SAP, incor-
porates an additional two conditions for a Steiner arborescence to be feasible.
First the number of included arcs is not to exceed a predetermined bound, called
hop limit. Second, all terminals have to be leaves. The cut formulation (Formu-
lation 1) used by SCIP-Jack can be easily extended to cover this variation by
adding one extra inequality bounding the sum of all (binary) arc variables (de-
noted by ya) and removing for each terminal all outgoing arcs.
Still, the hop limit has signiﬁcant implications for the presolving and heuris-
tics approaches: Many of the presolving techniques remove or include edges from
the graph if a less costly path can be found, even if this involves taking more
edges. Hence, the presolving techniques currently implemented in SCIP-Jack
are not able to produce a valid graph reduction. Likewise, the heuristics currently
implemented do not take into account the hop limit, so an identiﬁed solution
may not be feasible. Therefore, a simple variation of the constructive heuristic

4 From single core to distributed parallel
SCIP has two parallel extensions ParaSCIP [27] and FiberSCIP [28], which
are built by using the Ubiquity Generator Framework (UG) [28]. In order to
make a solver for a speciﬁc problem, users ofSCIP can use their problem speciﬁc
pugins as is for parallelization just by adding a small glue code and linking to
one of the UG libraries.
In this way, users obtain their own problem speciﬁc parallel optimization
solver, which can do parallel tree search on a distributed memory computing
environment. The mains features of UG are: several ramp-up mechanisms (the
ramp-up is the process from the begining of the computation until all available
solvers become busy), a dynamic load balancing mechanism for parallel tree
search, and a check-pointing and restarting mechanism. For more details about
the parallelization, see [27, 28].
We present computational results for the open instances of the PUC test set
from SteinLib. However, it must be noted that the parallel version of SCIP-
Jack can handle all of the variants presented throughout this paper. The main
purpose of the parallel runs is to provide the optimal solutions to as many
instances as possible. The development of the sequential and the parallel version
of SCIP-Jack had been continuing concurrently, so our results for the open
instances were obtained by using an intermediate development code. When the
development code made a signiﬁcant improvement in the sequential version, we
just restarted the computation by giving the best incumbent solution found so far
and when the code change was not signiﬁcant, we continued the computation
from a check point of the previous run. For the computations, we used PC
clusters and supercomputers as they were available. We conducted a few big
jobs which used over 4,000 solvers, but still, most of the computations were

5 Conclusions
We have shown that incorporating the mathematical progress of the last 15 years
into a well-known model for Steiner trees can have a signiﬁcant impact in several
dimensions. First, the amount of problem speciﬁc code is notably reduced while
at the same time the number of general solution methods available, e.g., cutting
planes, has increased and will be kept up-to-date just by the continuous improve-
ments in the framework. Furthermore, the opportunity to solve instances in a
massively parallel distributed memory environment has been added at minimal
cost.
The use of a general MIP solver allows us to be extremely ﬂexible with the
model to be solved. We were able to support solving nine variants of the Steiner
Tree problem with the same code, and the support of further restrictions in the
model is straightforward. Using all of this prebuilt-technology we were able to
solve three previously unsolved instances and improve the best known solution

===== PAGE 17 =====

for another 13 instances. And ﬁnally, to the best of our knowledge this is the ﬁrst
time that a powerful exact Steiner tree solver code is available in source code to
the scientiﬁc community. We hope that this will foster the use of Steiner trees
in modelling real-world phenomena as has already been the case in genetics.
